Two corrections before anything else

You asked for a cron job link and a hidden link. Neither exists, and I would rather tell you that than hand you something invented.

There is no cron job in this product

I searched the whole repository — Python, TypeScript, render.yaml — for any scheduled task, cron entry, APScheduler or Celery beat. There is none. Nothing runs on a timer: no nightly recalculation, no scheduled report, no cleanup sweep. Every action happens because a person clicked something, or (once PR 3 lands) because a worker picked a job off the queue.

The one thing that looks time-based is support-grant expiry, and it deliberately is not swept by a job: the expiry is derived from a stored timestamp at read time, so a lapsed grant stops working the instant it lapses whether or not anything ran. That design choice is why no cron is needed for it.

There is no hidden link, and there should not be

The admin pages are /admin/users and /admin/support. They are ordinary routes listed in the codebase, not secret URLs. What protects them is a role check on every request — require_admin returns 403 unless User.role == "admin" — not the fact that the address is hard to guess.

That distinction matters for a product holding payroll data. A secret URL is a password that gets pasted into chat, appears in browser history and leaks in a screen share, and grants full access to anyone who ends up with it. Knowing the address of /admin/support gets an ordinary user a 403 and an audit entry. If you want a colleague to reach the admin pages, the answer is to grant them the admin role, not to send them a link.

Product structure

Four tiers, one repository, two deployed services. No message broker, no cache layer, no third service to secure.

Browser
Next.js 14 App Router · React 18 · TypeScript · Tailwind · TanStack Query · Recharts. Light-only sky-blue palette. Signed out, the shell renders a brand frame and a Sign in button and nothing else — no nav, no settings labels, no entity names.
↓ same-origin /api/proxy/…
Next.js server
Thin relay. Forwards to BACKEND_URL, dropping content-encoding and content-length together — keeping the second while dropping the first silently truncates decompressed JSON, which cost a day to find once already.
↓ HTTPS
API
FastAPI · SQLAlchemy 2.0 typed models · Pydantic v2 · JWT auth. Every response is the envelope {success, data, error}. 22 routers; every tenant-scoped one resolves the caller's entity from the X-Entity-Id header.
↓
Engines
39 service modules. Five statutory engines (PF, ESIC, PT, LWF, income tax), attendance and arrears rules, cost model, bank reconciliation, JV builder, risk scoring, masking, audit. 73 finding codes across 14 families. The rule engine evaluates formulas through a restricted Python AST — fixed operator and function whitelist, no imports, no attribute access.
↓
PostgreSQL 16
43 tables. Also the job queue: validation_jobs claimed with SELECT … FOR UPDATE SKIP LOCKED. Schema managed by create_all plus hand-rolled idempotent dialect-aware migrations in app/migrations.py.

Tenancy, in one paragraph

An Organization holds many Entities (the employers whose payroll you check). A user gets an OrgMembership with one of four roles, and EntityAccess rows decide which entities they see. Write operations require owner, manager or analyst; viewer is read-only. The X-Entity-Id header selects the active entity on every request, and a value the caller has no access to returns 404 — not 403, because which entities exist is not something the API should confirm to a stranger.

The claim that makes the product sellable

Peopleopslab never runs payroll. It checks the register your payroll system produced. That is not a limitation to apologise for — it is the reason it can independently check one. An HRMS auditing its own output is marking its own homework.

The path a client's June payroll takes, from the file they export to the exceptions you hand back.

Two design rules worth knowing before you demo it

Silence is never a pass

A month with no bank file is reported unreconciled, not clean. A missing minimum-wage rate is a finding that says so, not a quiet skip. Reporting "nothing disagreed" when nothing was checked is the most dangerous answer a compliance tool can give.

Absent and zero are different claims

A register that never mentioned ESI must not look like one that deducted nothing. Only the statutory measures a register actually states are captured, and the reconstruction that feeds the background worker preserves that distinction — with a test that proves it.

The four organisation roles

RoleCan do
ownerEverything, including configuration and managing people
managerEverything operational, plus configuration

Platform admin is separate and is not one of these. It is a flag on the user account (User.role == "admin"), and on its own it grants no access to any client's payroll.

Admin and support access

The mechanism you actually have, instead of the hidden link you asked for.

A platform administrator can see which organisations exist and manage platform accounts. They cannot read a single client's payroll figure. To do that they must open a break-glass support grant, and every rule around it exists to keep it a documented support mechanism rather than a back door.

Never implicit

Nothing widens access as a side effect. An admin with no grant reads no client data, exactly as if they had no account.

Never silent

Opening a grant writes to the client's audit trail, not a separate staff log they cannot see. So does closing it, and so does the client revoking it.

Cannot outlive its box

Default 60 minutes, maximum 480. Expiry is derived from a timestamp at read time, so a lapsed grant stops working the moment it lapses — no sweeper to fail.

Read-only, and masked

A grant never carries write access and never unmasks employee identifiers. Both are recorded on the grant, so what a past session could see stays true even if the product later gains a wider mode.

A reason is required and must be at least 12 characters — a reason short enough to be meaningless is not a reason. Each client organisation sets its own policy: break_glass (an admin may open one), approval_required, or disabled (nobody can, ever).

Making yourself an admin

The first user to sign up on a fresh installation becomes the platform admin. After that, an existing admin promotes others from /admin/users. There is no environment variable, no seed account with a default password, and no console command — deliberately, because each of those is a credential that ends up in a repository.

Testing points

Five things you can run. The first four take minutes; the fifth is the one with a deadline.

1 · The unit suite — 844 tests

cd backend
python -m pytest tests/ -q                 # SQLite, ~2m45s

DATABASE_URL=postgresql+psycopg2://user:pass@host/db \
  python -m pytest tests/ -q               # PostgreSQL, ~2m56s

Run it on both. They are not interchangeable: SQLite ignores foreign keys by default and has no FOR UPDATE SKIP LOCKED, and both differences have hidden real bugs in this codebase already.

Note: run pytest tests/, not bare pytest — the backend root holds live-server scripts that pytest would try to collect and fail on.

2 · End-to-end against a running deployment — 41 checks

cd backend
PEOPLEOPSLAB_BASE_URL=https://payroll-saas-api-r6a8.onrender.com \
  python e2e_deployed.py

Signs up a throwaway organisation, configures it, uploads three months of master, attendance and registers, validates, reconciles a bank file, builds a JV and exports it to Tally. Exits non-zero if anything fails, so it works as a release gate. Safe against production — entity scoping keeps everything it creates inside its own organisation — but it writes, so don't aim it at a tenant whose audit trail you care about.

It asserts the single most important production setting: that an unauthenticated request is refused. A deployment that answers /api/org/entities without a token is serving payroll to the internet.

3 · Frontend

cd frontend
npx tsc --noEmit      # types
npm run lint          # eslint
npm run build         # production build

The API's boot log is the other thing to read. It states the environment, which database it actually connected to, the CORS origins and whether anonymous access is on:

anonymous=False in production is the line that matters. validation_workers is new — see the open items.

5 · The statutory verification worksheet

cd backend
python tools/statutory_worksheet.py worksheet.xlsx

Generates the 164-value sign-off workbook — income tax for the current FY, PF and ESIC, PT for 22 states, LWF for 15 — reading the values out of the running application rather than a typed copy. Give it to a payroll professional with one instruction: fill every yellow cell. This is the GO_LIVE §D6 gate, and until it is signed you cannot defensibly bill anyone for a compliance finding.

What to check by hand before a demo

  • Sign out and load /dashboard — you should see the brand frame and a Sign in button, and no navigation words at all.
  • Open the company picker on the portfolio and switch companies — the figures should follow.
  • On Bank payments, set the period to a month that has data. It defaults to the current calendar month, so a June close shows an empty September until you change it.
  • First page load after an idle period takes 30–50 seconds. That is the free tier waking, not a failure.

Validation still runs on the HTTP request path

The queue exists and the worker that drains it is built, tested and merged — verified live at 5,000 employees in 25 seconds, and a job abandoned mid-run was reclaimed and finished. But nothing enqueues yet: /api/payroll/validate is still synchronous, so a large register still times out. PR 3 switches the endpoint to return 202 {job_id} and moves the upload page to polling. That is the one that removes the timeout.

Statutory rates are not signed off

Smaller things

Both web services are on Render free tier and sleep after 15 minutes idle — a prospect clicking your demo link waits 30–50 seconds. The company picker defaults to an entity with no data when another in the same organisation has some. Bank payments defaults to the current calendar month rather than the latest month with data. Charts with two to four series still rely on a legend rather than direct labels. The Financial impact tile on the results page truncates its value to ₹3,19,…. The old indigo #6366f1 survives in the KPI card, the employee-detail chart and the keyboard focus outline — none of which appear in the manuals, so they were left rather than widening a documentation change into a palette sweep.
